# API

API предоставляет доступ к функциям сервиса: Telegram-бот получает через него ответ на сообщение, а разработчик смотрит выбранные примеры и запускает оценку реранкера.

## Основные операции

- `POST /replies` - получить ответ бота на сообщение из чата (US-01, UC-01);
- `GET /replies/{replyId}/examples` - получить примеры, которые реранкер выбрал для ответа, с оценками (US-02);
- `POST /evaluations` - запустить оценку реранкера и бейзлайна BM25 на тестовой выборке (US-03);
- `GET /evaluations/{evaluationId}` - получить статус оценки и метрики Recall@1, Recall@5, MRR, NDCG@10 (US-03).

## Ошибки

Все ошибки возвращаются в одном формате: машинный код `code` и описание `message`.

| Код HTTP | Когда |
|---|---|
| 400 | Пустой текст сообщения или неизвестная часть выборки |
| 404 | Ответ или оценка с таким идентификатором не найдены |
| 503 | Модели или индекс реплик ещё не загружены |
| 504 | LLM не ответила за отведённое время, бот промолчал |

## Спецификация

Полное описание API находится в файле [`openapi.yaml`](openapi.yaml) (OpenAPI 3.0.3). Его можно открыть в [Swagger Editor](https://editor.swagger.io/).

## Проверка документации

Проверка основного endpoint `POST /replies` по Swagger UI:

- **HTTP-метод:** POST.
- **Какие данные передать:** JSON с идентификатором чата `chatId`, текстом `text` и необязательным флагом `debug`.
- **Обязательные поля:** `chatId` и `text` (текст от 1 до 4096 символов).
- **Что возвращается при успехе:** код 200 и объект `Reply`: идентификатор ответа, текст, число использованных примеров, признак `fallback`, версия реранкера, а при `debug = true` ещё и сами примеры.
- **Возможные ошибки:** 400 (пустой текст), 503 (модели не загружены), 504 (LLM не ответила вовремя).
