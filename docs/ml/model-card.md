# Model Card

## Общая информация

**Название модели:**  
bge-reranker-v2-m3

**Источник:**  
[Hugging Face Hub: BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)

**Автор / организация:**  
BAAI (Beijing Academy of Artificial Intelligence)

**Задача модели:**  
Реранкинг (cross-encoder): модель получает запрос и текст-кандидат вместе и возвращает оценку их релевантности. Базовая модель - bge-m3, около 0,6 млрд параметров. Лицензия Apache-2.0.

**Язык:**  
Многоязычная (в карточке указано «Multilingual», конкретный список языков не приведён).

## Использование в проекте

Модель выполняет роль реранкера в сценарии UC-01 и в операции `POST /replies` (см. [API](../api/index.md)).

1. Поиск BM25 находит 50 реплик-кандидатов для входного сообщения из чата.
2. Сервис передаёт модели 50 пар «сообщение и кандидат».
3. Модель возвращает оценку для каждой пары. Пять пар с наибольшей оценкой становятся примерами в запросе к LLM.
4. Оценки сохраняются в поле `rerankerScore` и доступны разработчику через `GET /replies/{replyId}/examples` (US-02).

Готовая модель используется как стартовая точка и как сильный бейзлайн. Её качество сравнивается с BM25 по метрикам Recall@1, Recall@5, MRR и NDCG@10 через `POST /evaluations` (US-03). Если качества не хватит, модель дообучается на датасете из [Data Sheet](dataset.md).

## Входные данные

Пара текстов: запрос (в проекте это входное сообщение из чата) и текст-кандидат (реплика-ответ из сохранённых пар). В примере авторов используется ограничение длины `max_length=512` токенов.

## Выходные данные

Одно число - оценка релевантности пары: чем больше, тем лучше кандидат подходит к запросу. Сырые оценки могут быть отрицательными. По описанию авторов, параметр `normalize=True` применяет сигмоиду и переводит оценку в диапазон от 0 до 1.

## Метрики качества

Авторы приводят сравнение на бенчмарках BEIR, CMTEB-retrieval, MIRACL (многоязычный) и llama-index. Числовые результаты в тексте карточки не приведены, они показаны только на изображениях.

На задаче проекта (подбор естественного ответа в чате) метрики авторами не указаны: это не их сценарий. Их предстоит измерить самостоятельно.

## Ограничения

Ограничения авторами модели не указаны. Ниже - анализ для нашего проекта.

**Потенциальное ограничение для нашего проекта:**  
Модель обучалась оценивать релевантность документа поисковому запросу, а в проекте нужно оценивать, насколько реплика подходит как живой ответ в беседе. Это другая задача: подходящий ответ часто не повторяет слов сообщения.

**Потенциальное ограничение для нашего проекта:**  
Многие сообщения в чатах очень короткие («да», «ага», «ору»). В таких парах мало информации, и оценки модели для них могут быть близкими и малоинформативными.

**Потенциальное ограничение для нашего проекта:**  
Около 0,6 млрд параметров. Оценка 50 пар на каждое сообщение может работать медленно без GPU и задерживать ответ бота.

**Потенциальное ограничение для нашего проекта:**  
Качество на разговорном русском языке с жаргоном, опечатками и матом авторами не оценивалось и требует проверки на нашей тестовой выборке.

## Не рекомендуется использовать

- Для принятия решений о людях (модерация, блокировки, оценка участников чата) - модель оценивает только связь двух текстов.
- Как фильтр токсичного или опасного содержимого: для этого модель не предназначена, нужен отдельный фильтр.
- Как генератор ответов: модель ничего не пишет, она только ранжирует готовые реплики.
